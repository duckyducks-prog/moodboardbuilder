# Third-party platforms and Seedance 2.x photoreal face inputs (as of Oct 2026)

> **Method note:** Direct page fetches (WebFetch/curl) and GitHub API reads for the third-party repos were blocked by the session's network and repo policy. Every finding below comes from search-engine extracts of the cited pages, not from reading the full pages. Treat exact quotes as close paraphrases and confirm them before publishing. "Verified" here means the point appears in the platform's own docs or in ByteDance docs. "Claim" means a vendor blog or marketing page, or a single unconfirmed report.

## Q0. Baseline: what ByteDance's block is and which legitimate routes exist

### Takeaway
ModelArk/Volcengine returns HTTP 400 `InputImageSensitiveContentDetected.PrivacyInformation` (with a parallel `InputVideoSensitiveContentDetected.PrivacyInformation`) when its classifier decides an input *may* be a real person. The decision is per image, so photoreal AI-generated faces are often caught too. ByteDance documents three sanctioned routes:
1. trusted outputs from its own models under the same account
2. preset or private virtual-portrait assets referenced as `asset://<id>`
3. authorized real-person assets created through ByteDance liveness verification

Any third-party platform that "supports faces" is using one of these routes.

### Cited Findings
- ByteDance ModelArk docs, as quoted by a third party, say: "Seedance 2.5 and Seedance 2.0 series models do not support directly uploading reference images/videos that contain real human faces". The error is HTTP 400, and resending the same file gives the same result. — [SeedRouter](https://seedrouter.ai/blog/seedance-real-person-error); [Segmind error guide](https://blog.segmind.com/seedance-2-0-error-guide-every-error-explained-with-fixes/)
- The error means "the input classifier considered the image a possible real-person image". That does not prove the image shows a real person. — [YingTu](https://yingtu.ai/en/blog/seedance-2-0-human-face)
- The three documented routes are (a) face-containing outputs generated by certain ByteDance models under the same account, reused as inputs (one guide says within 30 days), (b) a preset digital-character library referenced by `asset://` IDs, and (c) authorized real-person assets that require the person's consent. — [Clipdance](https://clipdance.ai/blog/seedance-2-real-face-workaround); [MindStudio](https://www.mindstudio.ai/blog/seedance-2-0-content-restrictions-workarounds)
- BytePlus ModelArk documents a "Private virtual portrait library" / private trusted asset library for Seedance 2.0 and 2.5. Trusted assets added there go into your private asset library and can be used in generation. — [BytePlus docs 2333565](https://docs.byteplus.com/en/docs/ModelArk/2333565)
- ByteDance's Seed launch post says real human portraits used as subject references require "identity verification or prior legal authorization". — cited via [Freepik/Krea search summary of Seed launch post; secondary](https://reapi.ai/blog/seedance-not-eligible-explained)
- VicSee (vendor) dates the restriction: ByteDance suspended real-face uploads on 10 Feb 2026. — [VicSee](https://vicsee.com/blog/seedance-2-0-face-workaround)
- **Evasion warnings.** YingTu advises against "disguising the same portrait" and retrying. Several guides warn that cropping, blurring, sunglasses and grid overlays are unreliable, can fail at the output filter after credits are spent, and work around a consent safeguard. Some sites (for example a lumiying.com "grid overlay" page and YouTube "bypass" videos) promote such tricks. They are recorded here only as something to avoid. — [YingTu](https://yingtu.ai/en/blog/seedance-2-0-human-face); [Clipdance](https://clipdance.ai/blog/seedance-2-real-face-workaround)

### Inferences
- No reseller can turn off the classifier, because it runs at ByteDance's model layer. A reseller "supports faces" only by wiring one of the three ByteDance routes into its product, usually by uploading the image to the asset library on the user's behalf.

### Gaps
- I could not read the BytePlus doc directly; the CONNECT to docs.byteplus.com was refused.

## Q1. API resellers: do Seedance 2.x endpoints accept face images, and how?

### Takeaway
None of these resellers accepts photoreal faces as a plain image URL. The ones that support faces do it through the asset library:
- **APIYI:** documented manual asset-group upload, plus a liveness path for real people.
- **PiAPI:** Asset Library with review.
- **Cloudflare Workers AI:** a `use_virtual_avatar` flag that routes inputs into ByteDance's virtual-avatar library.
- **OrcaRouter:** asset-library docs.
- **EvoLink:** claims real faces after verification.

fal.ai, Replicate and WaveSpeed show no asset or face option in what I could find. Runware, Kie.ai and LaoZhang are unclear.

### Cited Findings
**APIYI (verified, own docs)**
- APIYI's docs say Seedance 2.0 has built-in deepfake filtering and won't take real-face reference images directly. Blocked requests get HTTP 400 and are not charged. — [APIYI asset library](https://docs.apiyi.com/en/api-capabilities/seedance2/asset-library); [APIYI FAQ](https://docs.apiyi.com/faq/seedance2-asset-face-reference)
- Images are *not* auto-uploaded to the asset library. You create an asset group, upload, poll until the asset is Active, then reference `asset://<id>`. Asset-management calls go directly to Volcengine. Generation goes through the APIYI gateway. — same sources
- APIYI describes two paths: liveness verification for real people, and a separate automatic ingest path for virtual avatars with no real-world counterpart. — [APIYI FAQ (en)](https://docs.apiyi.com/en/faq/seedance2-asset-face-reference)
- **Claim:** APIYI says its virtual-face whitelist access is free and real-person verification is free on its channel, whereas on the official channel it is a separately purchased add-on. — [APIYI overview](https://docs.apiyi.com/en/api-capabilities/seedance2/overview)

**OrcaRouter (own docs)**
- Assets are referenced as `asset://<asset_id>` in the content list. The prompt refers to them by type and position, such as "[Image 1]". Only Active assets can be used. — [OrcaRouter asset library](https://docs.orcarouter.ai/seedance-video/asset-library)

**Cloudflare Workers AI (verified, own docs)**
- The boolean `use_virtual_avatar` (default false) on Seedance 2.0, 2.0 Fast, 2.0 Mini and 2.5 routes image inputs (`image`, `reference_images`, `last_frame_image`) "through ByteDance's trusted virtual avatar asset library before generation". It is "intended for AI-generated/virtual character avatars that would otherwise be blocked by face or deepfake detection". This is automatic virtual-portrait upload behind one flag. It is not a route for real people. — [Cloudflare Seedance 2.0 Fast](https://developers.cloudflare.com/ai/models/bytedance/seedance-2.0-fast/); [Cloudflare Seedance 2.5](https://developers.cloudflare.com/ai/models/bytedance/seedance-2.5/)

**PiAPI (own pages)**
- Face references must be uploaded to PiAPI's Asset Library and pass review/verification before they can be used in its "less-restriction" modes. PiAPI has a tutorial for a consented-person face-reference workflow. — [PiAPI Seedance 2.0](https://piapi.ai/seedance-2-0); [PiAPI real-face tutorial](https://piapi.ai/blogs/seedance-2-real-face-asset-tutorial)
- Price: $0.053/s at 480p and $0.106/s at 720p (page about 6 months old). — [PiAPI](https://piapi.ai/seedance-2-0)

**EvoLink (claim)**
- EvoLink says real-face upload is supported after verification, at the same per-second rates as other modes with no premium. Its rates (dated April 2026) are:

  | Tier | 480p | 720p |
  |---|---|---|
  | Standard | $0.092/s | $0.199/s |
  | Fast | $0.074/s | $0.161/s |

  — [EvoLink real-human guide](https://evolink.ai/blog/seedance-2-0-real-human-video-api-guide); [EvoLink pricing](https://evolink.ai/blog/seedance-2-0-pricing-api-cost-guide)

**useapi.net**
- useapi.net has a tutorial titled "Seedance 2.0: Using Real Faces". I could not see the details. — [useapi.net](https://useapi.net/blog/260415)

**fal.ai (own pages)**
- The schemas for 2.0 text-to-video, image-to-video and reference-to-video (up to 9 images, 3 videos, 3 audio), the Fast variants, and 2.5 reference-to-video list `image_url(s)`, `end_image_url`, `video_urls`, `audio_urls`, `seed` and `end_user_id`. They show **no** asset, virtual-avatar or real-person parameter. — [fal 2.0 reference-to-video](https://fal.ai/models/bytedance/seedance-2.0/reference-to-video); [fal 2.5 reference-to-video](https://fal.ai/models/bytedance/seedance-2.5/reference-to-video)
- **Claim:** Third-party guides say the model layer "uniformly returns a blocked error" on Replicate, fal.ai, WaveSpeed and similar hosts. — [ruoqijin](https://ruoqijin.com/blog/seedance-access-and-face-policy); [Segmind](https://blog.segmind.com/seedance-2-0-error-guide-every-error-explained-with-fixes/)
- openstory, which uses fal, has a pricing issue that references fal endpoints, and its Seedance face handling sends Ark requests (see Q4). — [openstory #1605](https://github.com/openstory-so/openstory/issues/1605)

**Replicate**
- I found no Replicate documentation on faces. Third-party guides say it inherits the same block. — [Segmind](https://blog.segmind.com/seedance-2-0-error-guide-every-error-explained-with-fixes/)

**Kie.ai (marketing only)**
- Kie.ai's page title is "Seedance 2.0 API with Realistic Human Support" and it mentions "virtual human video creation". Its listed input schema has only first and last frame images, with no documented real-face or asset mechanism. — [Kie.ai](https://kie.ai/seedance-2-0)

**WaveSpeed and Runware**
- WaveSpeed is listed among channels where real-person references return a blocked error. — [ruoqijin](https://ruoqijin.com/blog/seedance-access-and-face-policy)
- For Runware, I found nothing face-specific.

**LaoZhang**
- LaoZhang has Seedance 2.0 and 2.5 docs with token-based pricing. It estimates a 5 s 720p clip at about $0.90 (2.0) and about $0.73 (Fast). I saw no face or asset details in the extract. — [LaoZhang docs](https://docs.laozhang.ai/en/api-capabilities/seedance2-video-generation)

**APIMODELS (claim, checked 2026-09-30)**
- Seedance 2.0 costs $0.092/s at 480p, $0.197/s at 720p and $0.492/s at 1080p.
- It says the "seedance-2.0 line accepts real-person references" while the cheaper "Dreamina line" does not.
- I could not verify the mechanism. — [apimodels.app](https://apimodels.app/access/seedance-api-pricing)

**Variant claims ("Portrait" tier)**
- **Claim:** Clipdance and seedance2.so say they offer a "Portrait model tier" that supports real-person content. Both are vendors, and no ByteDance doc confirms a separate model variant. — [Clipdance](https://clipdance.ai/blog/seedance-2-real-face-workaround); [seedance2.so](https://seedance2.so/blog/seedance-2-real-face-workaround)

### Inferences
- The resellers that genuinely work do so because the reseller's ByteDance account has asset-library access (APIYI calls this a "virtual-face whitelist"). The face itself becomes an `asset://` ID created either by an automatic virtual-portrait ingest (Cloudflare flag, APIYI virtual path) or by a liveness flow for real people. A "Portrait variant" is most likely marketing for this asset routing, not a different model. That is speculation.
- Pricing: no reseller I found charges a separate per-generation premium for asset or face use. APIYI implies that ByteDance's official real-person verification is a paid add-on.

### Gaps
- I could not read the fal, Replicate, Runware or WaveSpeed docs in full to confirm that they have no face option. I also found no first-hand error reports for them.
- I found no Kie.ai mechanism detail and no asset pricing from any provider.

## Q2. Creative apps (Higgsfield, Freepik, Krea, Leonardo, Pollo, Dreamina/CapCut, OpenArt, ComfyUI, KreadoAI)

### Takeaway
ByteDance's own apps (CapCut/Dreamina) block real faces in the UI. ComfyUI is the clearest documented legitimate implementation:
- AI-generated portraits need no extra check, because they are automatically turned into assets.
- Real people go through a one-time ByteDance liveness check that produces a reusable Group ID.

Higgsfield and Freepik were reported in April 2026 to accept realistic people, by a mechanism that was not disclosed. Krea, Leonardo, Pollo and OpenArt have no documented face policy.

### Cited Findings
**Dreamina / CapCut (ByteDance)**
- CapCut's launch (Mar 2026) said the model won't make videos from images or videos containing real faces. — [TechCrunch](https://techcrunch.com/2026/03/26/bytedances-new-ai-video-generation-model-dreamina-seedance-2-0-comes-to-capcut/)
- Dreamina's picker shows "Real human faces are not supported" and rejects uploads with "Face detected in your media. Try another one." — [reapi](https://reapi.ai/blog/seedance-not-eligible-explained); [aiafter40](https://www.aiafter40.com/capcut-dreamina-seedance-2-0-the-ai-video-generator-thats-putting-faces-on-hold/)
- I found no source describing a self-service liveness flow in Dreamina or CapCut.

**ComfyUI / Comfy Org (verified, own docs and blog)**
- The "ByteDance Create Image/Video Asset" node handles both cases:

  | Input | Process | Output |
  |---|---|---|
  | AI-generated portrait | "No extra check" | Asset |
  | Real person (first time) | Upload produces a verification link, then a liveness check on phone or browser ("<30s") | Group ID for the person plus Asset ID for the image |
  | Same real person, new photo | Pass the saved Group ID; the new face is compared with the original | Asset activated automatically on match |

  Verification is handled by ByteDance. — [Comfy blog](https://blog.comfy.org/p/unlock-seedance20-real-human-video-generation); [Comfy docs Real Human](https://docs.comfy.org/tutorials/partner-nodes/bytedance/seedance-2-0-real-human); [Comfy docs Seedance 2.0](https://docs.comfy.org/tutorials/partner-nodes/bytedance/seedance-2-0)

**Higgsfield and Freepik**
- **Claim:** A Japanese note (Apr 2026) reported that Seedance 2.0 on Higgsfield and Freepik "can now reference realistic people (not blocked)", and that Freepik opened access to individual users two hours after Higgsfield. — [note.com/creative_edge](https://note.com/creative_edge/n/n91b776e20b9d?hl=en)
- This conflicts with vendor guides that say Higgsfield "only expose[s] the standard model" and hits the same block. — [seedance2.so](https://seedance2.so/blog/seedance-2-real-face-workaround); [Clipdance](https://clipdance.ai/blog/seedance-2-real-face-workaround)
- Higgsfield's own tutorial exists, but no face policy appeared in the extracts. Seedance 2.0/2.5 requires plans above the $19 Starter tier. — [Higgsfield tutorial](https://higgsfield.ai/blog/generating-with-seedance-2-0); [Krea on Higgsfield pricing](https://www.krea.ai/blog/higgsfield-pricing-explained-2026-unlimited-credits-and-real-monthly-costs)
- Freepik launched Seedance 2.0 for Business and Enterprise first, with verification required for Business. — [X/AiTechPerks](https://x.com/AiTechPerks/status/2041980034869830060)

**Krea and OpenArt**
- Krea is on all paid plans. Its marketing says characters "stay recognizable", but it has no face-upload policy. — [Krea](https://www.krea.ai/index/seedance-2)
- OpenArt's model page claims "consistent faces". A vendor guide lists OpenArt among standard-model platforms that hit the block. — [OpenArt](https://openart.ai/ai-model/seedance-2-0/); [Clipdance](https://clipdance.ai/blog/seedance-2-real-face-workaround)

**Leonardo and Pollo**
- I found no sources.

**KreadoAI**
- KreadoAI launched a "Virtual Avatar Library" for Seedance 2.0 (Jun 2026). It offers pre-designed virtual characters plus avatar assets uploaded by users. — [KreadoAI](https://www.kreadoai.com/article/seedance-2-0-virtual-avatar-library)

**Adobe**
- An Adobe community thread reports Seedance (presumably inside Adobe Firefly) falsely flagging AI-created faces as human. — [Adobe Community](https://community.adobe.com/questions-404/seedance-dont-work-correctly-detects-human-face-and-is-not-human-face-is-created-with-ia-1630600)

**Seedream outputs as references**
- One guide recommends generating the character with Seedream, which suggests the trusted-output route. — [socialart.ai](https://socialart.ai/blog/seedance-2-0-reference-image-prompt-guide)

### Inferences
- If Higgsfield and Freepik really accept realistic faces, the most plausible legitimate mechanisms are an enterprise or whitelisted ByteDance account with automatic virtual-portrait ingest, or trusted-output reuse from their own image models. Neither is documented. This is speculation.

### Gaps
- I found no current (Q3 2026) primary documentation for Higgsfield, Freepik, Krea, Leonardo, Pollo or OpenArt on face handling.
- The April Higgsfield and Freepik report is unconfirmed and may be outdated.

## Q3. OpenRouter (/api/v1/videos, bytedance/seedance-2.0 and 2.5)

### Takeaway
OpenRouter's docs describe `input_references` (image/audio/video) and `frame_images` with HTTPS URLs only. I found **no** documentation of `asset://` support, a virtual-avatar or portrait option, provider routing for face handling, or the face block itself. Comfy's own router collapses the face error into a generic `content_policy_violation`. The ComfyUI PR does not identify OpenRouter, so whether OpenRouter does the same is unconfirmed.

### Cited Findings
- OpenRouter's reference-to-video cookbook says to use `input_references` for visual guidance and `frame_images` for exact frame control, with "stable, directly downloadable image URLs". — [OpenRouter cookbook](https://openrouter.ai/docs/cookbook/video-generation/reference-to-video); [Video generation guide](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)
- Image references work with all providers. Audio and video references work with providers that support them, including BytePlus Seedance gen 2 and newer. — [OpenRouter InputReference](https://openrouter.ai/docs/client-sdks/python/components/inputreference)
- OpenRouter's own Seedance 2.5 review says image references can carry "a face, a product, or a style". It does not mention the block. — [OpenRouter blog](https://openrouter.ai/blog/insights/seedance-2-5-review/)
- Seedance 2.5 was added in August with up to 50 image, video and audio references per request (secondary report). — [runtimewire](https://runtimewire.com/article/openrouter-bytedance-seedance-2-5-video-api)
- A `data:` URI in `input_references` returned HTTP 400 ("only HTTPS URLs"), and a 400 on POST /videos created no job (no spend). — [Reid-Surmeier issue #101](https://github.com/Reid-Surmeier/Image-generation-pipline/issues/101)
- The model page describes text-to-video, image-to-video with first and last frame, and multimodal reference-to-video. No face restrictions appeared in the search extract. — [OpenRouter Seedance 2.0](https://openrouter.ai/bytedance/seedance-2.0); [llms.txt](https://openrouter.ai/bytedance/seedance-2.0/llms.txt)
- A third party (cellcog) claims that on Seedance 2.5 the provider's likeness filter blocks any reference containing a human face from any source, including the model's own frames. This conflicts with the trusted-output route. — [cellcog](https://cellcog.ai/blog/seedance-2-5-face-likeness-character-consistency/)

### Inferences
- OpenRouter appears to send plain URLs to BytePlus. Unless an `asset://` string is accepted as a URL (undocumented, and it fails the HTTPS-only check), photoreal faces on OpenRouter will hit the upstream block, and there is no documented virtual-avatar route. Users who need faces would have to go to ByteDance directly or to an asset-capable reseller.

### Gaps
- I could not access OpenRouter's Discord, changelog or Reddit threads, and no search result showed `asset://` or a provider-routing option for faces.
- I could not determine whether OpenRouter's error passes through `PrivacyInformation`.

## Q4. Community reports (GitHub, Reddit)

### Takeaway
Developer issues confirm that (a) photoreal *AI-generated* faces get blocked, (b) the fix projects adopt is detecting photoreal faces and routing them through the ByteDance asset library, and (c) routers often hide the specific error.

### Cited Findings
- **openstory #1927**, "Likeness check clears photoreal fictional characters, so Seedance blocks them": a photoreal render of an invented person was classified as animated, so it was sent to Ark as a plain URL and refused. The proposal is to treat any photoreal face as human whether real or fictional, so it goes through the likeness/asset path. Fix PR #1928 (29 Sep 2026; merge status unknown). Related issue #1847: stylised portraits of real people should still count as likeness. — [#1927](https://github.com/openstory-so/openstory/issues/1927); [PR #1928](https://github.com/openstory-so/openstory/pull/1928); [#1847](https://github.com/openstory-so/openstory/issues/1847)
- **ArcReel #2249** (Chinese, affects v0.28.0 and earlier): AI-generated realistic-person images used as reference or first frame get rejected with PrivacyInformation on Volcengine. Seedance 2.0 won't take face images by URL or Base64. The requested fix is integrating the Volcengine portrait asset library (`asset://`). — [ArcReel #2249](https://github.com/ArcReel/ArcReel/issues/2249)
- **Comfy-Org/ComfyUI_frontend PR #19638**, "tell users Seedance blocks realistic faces": the Router forwards the refusal only as `content_policy_violation` and drops the face code. The author found one photoreal AI portrait refused and another accepted, which suggests the classifier works per image. Related SDK PRs add `refusal_subject` (prompt, input image or output). — [PR #19638](https://github.com/Comfy-Org/ComfyUI_frontend/pull/19638); [comfy-python-sdk #192](https://github.com/Comfy-Org/comfy-python-sdk/pull/192)
- The ZeroLu "how to use real face in Seedance 2.0" community guide exists; I could not read its contents. — [GitHub ZeroLu](https://github.com/ZeroLu/seedance2.0-how-to/blob/main/how-to-use-real-face-in-Seedance2.0.md)
- A developer comparison of seven providers covers "real-person support" (contents not read). — [best-seedance-2-api](https://github.com/gracech0322-cmd/best-seedance-2-api)

### Inferences
- The consistent pattern among builders: detect a photoreal face, upload it to the asset library (virtual portrait for fictional people, liveness plus Group ID for real people), then send `asset://`. The ComfyUI node and Cloudflare's flag are productized versions of this pattern.

### Gaps
- I could not read Reddit (r/aivideo, r/StableDiffusion) or GitHub comment threads because of access restrictions, so the Reddit findings are missing.
- I could not confirm the merge status of openstory PR #1928 or Comfy PR #19638.
